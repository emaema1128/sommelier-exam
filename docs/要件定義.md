## 1. 背景と課題

- JSAのソムリエ/ワインエキスパート試験は出題範囲が非常に広い(各国の産地・品種・法律・歴史、酒類全般、チーズなど)。教本は毎年改訂され、覚える量が多い。
- 受験生は仕事をしながら勉強する社会人が多く、まとまった勉強時間を取りにくい。すきま時間に1問ずつ解ける手段が求められる。
- 二次のテイスティングは「たくさん飲まないと受からない」と思われがちだが、答案は**選択式**であり、品種・産地ごとに**選ぶべき用語の型**がある。型を覚え、手がかりから品種を絞り込む練習をすれば、飲まなくても点を取れる答案が書ける。練習用ワインの費用や飲酒量の負担も減らせる。

## 2. ターゲットユーザー

- 一次: JSAソムリエ/ワインエキスパート試験の受験生全般。
- 特性: 社会人(飲食店勤務・ワイン愛好家)が中心 / 通勤中などスマホで学習 / 試験シーズン(春〜夏)に学習量が集中。
- テイスティングの悩み: 練習用ワインの費用が高い / 毎日は飲めない / 何を選べば点になるのか分からない。
- 対象外(当面): WSET、三次試験(サービス実技)。

## 3. コアコンセプト

> **「国ごとに、すきま時間で、全範囲を網羅する。テイスティングは、飲まずに答案の型で受かる。」**

- 問題は国(産地)ごとに整理し、網羅性で勝負する。
- 間違えた問題は忘れかけた頃に再出題し(間隔反復)、覚える効率を上げる。
- テイスティングは「品種の型を覚える → 手がかりから品種を絞る → 型どおりに答案を埋める」を繰り返す。

## 4. 試験の前提(要確認: 最新の受験要項で確認すること)

| 試験 | 内容 | アプリでの扱い |
|---|---|---|
| 一次 | CBT方式の選択式。ソムリエ/ワインエキスパートで基本は共通 | 4択問題集・模擬試験(MVP) |
| 二次 | テイスティング(ワインとワイン以外の酒類)。答案は選択式(マークシート)。ソムリエは論述あり | **飲まずに答案を書く動線**(MVP)、論述は後回し |
| 三次 | サービス実技(ソムリエのみ) | 対象外 |

- Web調査の結果(2026-10-20、詳細は [二次試験_解答用紙_調査.md](二次試験_解答用紙_調査.md)):
  - 一次: CBT 120問・70分(公式)
  - 二次: ソムリエはワイン3+ワイン以外の酒2で40分、ワインエキスパートはワイン4+ワイン以外の酒1で50分。2026年度は9月28日に実施
  - 答案はすべて番号選択式のマークシート。項目ごとに選ぶ個数が指定され、選びすぎると0点とされる
  - 配点の約7割が外観・香り・味わいのコメント。品種を外してもコメントで点が取れる(「飲まずに受かる」方針の根拠)
- 解答用紙の用語は [templates/解答用紙_用語マスタ.csv](../templates/解答用紙_用語マスタ.csv) で年度つきのデータとして持つ。

## 5. アーキテクチャ方針

**スマホ優先のWebアプリ**。ホーム画面に追加して、アプリのように使える形(PWA)にする。

```
[ブラウザ(スマホ中心)]  web/
  Vue 3 + TypeScript + Vite(SPA。Vue Router で画面を切り替える)
  ├ 問題を解く画面・復習・模擬試験・学習状況
  ├ テイスティング: 型カード・推理ドリル・答案ドリル・本番模擬
  └ PWA: ホーム画面に追加 / 問題データをキャッシュしてオフラインでも解ける
         (オフライン中の回答は端末に一時保存し、通信が戻ったらサーバーへ送る)
        │
        │ JSON API(ログイン状態はセッションCookieで持つ)
        ▼
[サーバー(Go + PostgreSQL)]  server/
  ├ 認証: メール+パスワード(bcrypt)とセッションを自作
  │        + Googleログイン(OAuth 2.0 / OpenID Connect)
  ├ 学習記録: 回答履歴・正答率・復習予定・テイスティング答案の採点結果
  ├ 問題データ・品種プロファイルの保存と配信
  ├ 取り込み: スプレッドシート(CSV)→ Goのコマンド → DB
  │   取り込み時に形式チェック(重複ID、正解が選択肢にあるか、など)
  ├ 「誤りを報告」の受付
  └ 管理画面(問題の確認・公開/非公開の切り替え・誤り報告の確認)
```

- **技術を選んだ理由**: このアプリはGoを習得する場も兼ねる。そのため、サーバーはフレームワークに頼りすぎず、Goの標準ライブラリ中心で書く。画面側は既に慣れている Vue 3 + TypeScript のままにして、新しく覚えることをGoに集中させる。
- **ストア審査がない**ので、問題の追加はサーバーに取り込むだけで即時反映できる。
- **ログイン必須**にすることで、機種変更・PCとスマホの併用に対応でき、iPhoneのSafariによる端末内データ削除の問題も避けられる。
- **認証は自作する**。Laravelのスターターキットが用意していた機能(登録・ログイン・パスワード再設定・メール確認・セッション・CSRF対策)を、Goで1つずつ作る。セキュリティに関わるため、パスワードのハッシュ化・Cookieの属性・CSRF対策は定番の方法に従い、テストを書いて確かめる。
- **Googleログイン**は `golang.org/x/oauth2` と OpenID Connect のライブラリ(`go-oidc`)で作る。ログイン必須のアプリなので、ワンタップで登録できるようにして登録時の離脱を減らす。
- **Laravel版(`app/`)の扱い**: Go版が同じところ(登録・ログイン・Googleログイン)まで動くようになるまで、参考として残す。新しい機能は追加しない。Go版が追いついたら削除する。

### 技術スタック

| 分類 | 採用 | メモ |
|---|---|---|
| フロントエンド | Vue 3 / TypeScript / Vite / Vue Router | SPA。PWA化する |
| サーバーサイド | Go(標準の `net/http`) | Go 1.22以降の標準ルーティングを使う。フレームワークは必要になってから検討 |
| DB | PostgreSQL | 開発環境は Docker で立てる |
| DBアクセス | sqlc | 書いたSQLから型付きのGoコードを生成する |
| マイグレーション | goose | |
| 設計 | 軽めのDDD | domain(業務ルール)/ usecase(処理の流れ)/ handler・DB(外とのつなぎ)の3層程度。層を増やしすぎない |
| テスト | Go標準の testing / Vitest / Playwright | |
| CI | GitHub Actions | |
| インフラ | 未決 | 動く物ができてから費用を見て決める |

- 参考にしたコドモンの構成のうち、大人数・大規模向けのもの(マイクロサービス、gRPC、Kinesis、Pinpoint、DataDog、Flutter など)は採らない。

### Googleログインの扱い

| 論点 | 方針 |
|---|---|
| 事前準備 | Google Cloud でOAuthクライアントを作成し、本番・開発それぞれのリダイレクトURIを登録する。同意画面(アプリ名・プライバシーポリシーのURL)を設定する |
| 取得する情報 | メールアドレス・名前・GoogleのユーザーIDのみ(最小限) |
| 同じメールで両方の方法を使った場合 | Google側でメール確認済みなら、既存アカウントにGoogleログインを紐づける(アカウントを二重に作らない) |
| Googleだけで登録した人 | パスワードは持たない。あとから設定画面でパスワードを追加できるようにする |
| 退会 | 紐づけたGoogleの情報も含めて削除する |
- 問題は**スプレッドシートで書く**。エンジニア作業なしで大量に作れて、並べ替えや抜け漏れの確認もしやすい。

### 問題データの形(案)

| 項目 | 例 |
|---|---|
| id | `FR-BOR-0001` |
| 国 / 地域 / 分野 | フランス / ボルドー / AOC |
| 対象資格 | 共通 / ソムリエのみ |
| 問題文・選択肢・正解 | 4択 |
| 解説 | 自作の短い解説 |
| 教本年度 | 2026 |
| 難易度 | 1〜3 |
| 公開状態 | 公開 / 下書き |

- 教本の年度を持たせ、改訂時に「どの問題を見直すべきか」を追えるようにする。

### 品種プロファイル(テイスティングの中心データ・案)

「品種 × スタイル(産地・気候)」ごとに、答案の各項目で選ぶべき用語(模範解答)と、見分けるための手がかりを持つ。

| 項目 | 例 |
|---|---|
| id | `W-SB-LOIRE` |
| 色 / 品種 / スタイル | 白 / ソーヴィニヨン・ブラン / 冷涼産地(ロワール) |
| 模範解答 | 答案の各項目ごとに選ぶ用語(外観・香り・味わい・評価・温度・グラスなど) |
| 決め手の手がかり | 「青草・ハーブ」「高い酸」「樽なし」など、他の品種と見分けるポイント |
| 紛らわしい品種 | 同じ型に見える品種と、その違い(例: リースリングとの違い) |
| 出題頻度 | 高 / 中 / 低(よく出る品種から優先して学ぶため) |

- ワイン以外の酒類(蒸留酒・リキュールなど)も同じ形で持つ。

## 6. 機能要件

### MVP(フェーズ1)

#### 共通
1. **ログイン**: メール+パスワード、またはGoogleアカウントで登録・ログインする。資格(ソムリエ / ワインエキスパート)と試験日を初回に設定する。

#### 一次(筆記)
2. **国別の問題集**: 国 → 地域 → 分野の順に選び、4択で解く。1問ずつ解いてすぐ正誤と解説を表示する。
3. **間違えた問題の復習(間隔反復)**: 間違えた問題、自信がなかった問題を忘れかけた頃に再出題する。「今日の復習」を毎日の入口にする。
4. **模擬試験**: 全範囲からランダムに出題し、本番に近い形式・時間制限で解く。
5. **学習状況**: 国や分野ごとの正答率、進み具合(解いた問題 / 全問題)、苦手分野を表示する。

#### 二次(テイスティング): 飲まずに受かる動線

次の5ステップを順に進める。各ステップの結果は学習状況に反映し、苦手な品種は間隔反復で復習に回す。

| ステップ | 機能 | 内容 |
|---|---|---|
| 1 | **答案用紙を知る** | 答案の項目と選択肢を、本番と同じ並びで確認する。各項目で何を見られているかを短く解説する |
| 2 | **品種の型を覚える** | 品種プロファイルのカード。品種ごとの模範解答と決め手の手がかりを覚える。出題頻度の高い品種から順に出す |
| 3 | **推理ドリル(手がかり → 品種)** | 「淡いレモンイエロー、柑橘と青草の香り、酸が高い」のような描写を読み、品種・産地を当てる。紛らわしい品種を選択肢に混ぜる |
| 4 | **答案ドリル(品種 → 答案)** | 品種が示された状態で、答案の全項目を選ぶ。模範解答と比べて項目ごとに採点する |
| 5 | **本番模擬** | 品種を伏せた描写から、本番と同じ数・時間制限で答案を書き切る。品種を外しても、描写に合った用語を選べば部分点が入ることを体感させる |

6. **ワイン以外の酒類**: 同じ動線(型 → 推理 → 答案)で、蒸留酒・リキュールなども練習できるようにする。
7. **試験日から逆算した学習プラン**: 初回に設定した試験日までに、ステップ1〜5を終えられるように、毎日の目安(何品種覚えるか、何回模擬を解くか)を出す。

#### 運営者用
8. **問題・品種プロファイルの取り込みと管理画面**: CSVの取り込み、形式チェック、公開/非公開の切り替え、誤り報告の確認。

### フェーズ2以降

- 実際に飲んだワインの記録と、品種プロファイルとの比較(飲める人向けの補助)
- ソムリエ二次の論述対策
- Apple・X など、Google以外のログイン方法の追加(Googleログインと同じ OAuth の仕組みで追加できる)
- 広告(Google AdSense)・任意の寄付
- AIによる解説の補足(誤った情報が出るリスクがあるため、慎重に検討する)
- ランキング・受験生同士の交流
- 必要になればネイティブアプリ化(Capacitor で Vue の画面を包む等)

## 7. 非機能要件

- **スマホ優先**: 選択肢を画面の下半分に置き、片手・1タップで回答できるようにする。答案ドリルは項目が多いため、1画面に1項目ずつ表示する。
- **オフラインで動く**: PWA で問題データをキャッシュし、地下鉄でも解けるようにする。回答は通信が戻ったときにサーバーへ送る。
- **問題の追加で動作が重くならない**: 数千〜1万問規模を想定する。国・地域ごとに分けて読み込む。
- **個人情報**: 保存するのはメールアドレス・名前・GoogleのユーザーID(Googleログイン時)と学習記録のみ。パスワードは bcrypt でハッシュ化する。プライバシーポリシーと退会(データ削除)機能を用意する。
- **検索からの集客**: Webの強みを活かし、国・地域ごとの紹介ページなどを検索エンジンに載る形で用意する(問題の全文公開はしない)。SPAは検索エンジンに載りにくいため、紹介ページの作り方(サーバー側でHTMLを返す・静的に生成する等)は別途決める。

## 8. 収益(余地を残す)

- 広告: Google AdSense。回答画面ではなく、区切りのいい場面(10問終了時など)にだけ出す。勉強の集中を邪魔しないことを優先する。
- 寄付: Webなのでアプリ内課金の制約はない。外部の寄付サービスやStripeの決済リンクを使える。
- 運営費: サーバー代が必要。MVPは安価なVPSやレンタルサーバーで始める。

## 9. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| 問題・品種プロファイルを作る量が膨大 | 公開が遅れる・網羅できない | 国ごと、出題頻度の高い品種ごとに作った順に公開する。スプレッドシートで量産する。取り込みと形式チェックを自動化する |
| 「飲まずに受かる」の打ち出し方 | 誇大な宣伝と受け取られる・期待外れの評価 | 「合格保証」とは書かない。「答案の型で点を取る」「練習用ワインの費用を減らす」と打ち出す。飲める人には実飲との併用を勧める |
| 二次の答案形式の変更 | 答案用紙・模範解答の作り直し | 答案の項目と選択肢をデータとして持ち、画面にハードコードしない |
| ログイン必須による離脱 | 初回の登録で使うのをやめる人が出る | Googleログインでワンタップ登録できるようにする。登録項目を最小にする。トップページで中身(サンプル問題・品種カード)を見せてから登録を促す |
| 問題の誤り | 受験生の信頼を失う | 解説に根拠(教本の該当箇所)を書く。「誤りを報告」ボタンを付ける |
| 教本の著作権 | 削除要請・法的リスク | 教本の文章をそのまま写さず、自分の言葉で問題と解説を書く。過去問の再現として売り出さない |
| 問題の無断転載 | Webなので問題を抜き取られやすい | 問題はログイン後のみ表示する。APIに回数制限をかける |
| 毎年の教本改訂 | 古い情報が残る | 問題に教本年度を持たせ、改訂箇所を一括で見直せるようにする |
| 個人情報の漏えい | 信頼を失う | 保存する情報を最小にする。認証まわりは定番の方法(bcrypt、HttpOnly・Secure・SameSite付きのCookie、CSRF対策)に従い、テストで確かめる |
| 認証の自作による不備 | 不正ログイン・情報漏えい | Laravel版の動きを参考にし、登録・ログイン・パスワード再設定・Googleの紐づけの流れごとにテストを書く。公開前にセキュリティの観点で見直す |
| Goの学習に時間がかかる | 公開が遅れる | 簡単な機能(一次の4択)から作り、ログインは後に回す。インフラは動く物ができてから決める |
| 無料での運営費 | 継続できない | 小さいサーバーで始める。広告・寄付は後から足す |
